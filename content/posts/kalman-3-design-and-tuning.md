## 卡尔曼滤波设计步骤

设计一个离散卡尔曼滤波，本质是把“有哪些传感器、各自信噪比如何”翻译成状态空间模型。

在实际融合光流和加速度计时，按下面顺序落地：

1. **确定有哪些数据源**，各自测什么、什么性质
2. **给数据源定角色**：谁当预测输入、谁当观测输入
3. **写先验估计方程**（状态如何被推着走）→ 得到 `F`、`B`
4. **写观测方程**（状态被测成了什么）→ 得到 `H`
5. **五大公式循环**；缺 `Q`、`R`、`K` 等就按“缺什么补什么”推出来

下面逐步展开，并用本专题实例落地。

### 1. 确定待估计状态向量

先写清滤波器最终要输出什么，再补上为正确建模必须一并估计的误差项。

记状态向量为：

```
x = [待估量, 必须估计的误差项, ...]
```

本专题目标是一维速度；加速度计存在缓变偏置，若不估计会随积分发散，故把偏置也放进状态：

```
x = [v, b]^T
```

- `v`：速度（目标量）
- `b`：加速度计缓变偏置（误差项）

### 2. 划分各数据源的角色

先把数据源摊开，写清各自性质：

| 数据源 | 读数 | 性质 | 和目标量的关系 |
|--------|------|------|----------------|
| 加速度计 | `a_meas` | 有偏置、短时平滑 | 不直接测速度，需按物理关系积分才能推速度 |
| 光流 | `z_flow` | 无偏、噪声大 | 直接测速度 |

再把每个数据源归到两类之一，不要含糊：

| 角色 | 符号 | 含义 | 典型特征 |
|------|------|------|----------|
| 控制输入 | `u` | 驱动状态演化的已知量，进入预测方程 | 通常是“积分驱动”类量，如加速度、油门、力 |
| 量测输入 | `z` | 对状态的直接/间接观测，进入观测方程 | 通常是“直接看到状态”的量，如位置、光流速度 |

判断口诀：

- 能写成“状态如何被推着走”的输入 → 控制输入 `u`
- 能写成“状态被测成了什么”的输入 → 量测输入 `z`

本专题（对应前面互补滤波的两支）：

- 加速度计 → 控制输入 `u`（用加速度推速度 → **预测那一支**）
- 光流 → 量测输入 `z`（直接量到速度 → **测量那一支**）

同一物理传感器在不同建模选择下角色可能变化（例如光流也可只当量测、不用加速度计做控制量），但一套模型里角色要唯一、稳定。

### 3. 建立预测（过程）模型，写出 F、B

预测模型描述状态在一个采样周期 `dt` 内如何演化：

```
x_k = F · x_{k-1} + B · u_k + w
```

- `F`：状态转移矩阵
- `B`：控制输入矩阵
- `w`：过程噪声，协方差为 `Q`

本专题（欧拉离散，`u_k = a_meas`）：

```
v_k = v_{k-1} + dt · (a_meas - b_{k-1})
b_k = b_{k-1}
```

故：

```
F = [[1, -dt],
     [0,  1]]

B = [[dt],
     [0]]
```

注意 `F(1,2)` 是 `-dt`：偏置定义为 `a_meas = a_true + b`，预测时必须扣除 `b`。

这一步就是把“加速度计积分推速度”写成矩阵形式——互补滤波里的预测支路。

### 4. 建立观测（量测）模型，写出 H

观测模型描述量测如何由状态生成：

```
z_k = H · x_k + v
```

- `H`：观测矩阵
- `v`：量测噪声，协方差为 `R`

本专题光流直接量速度：

```
z = v + noise_flow
H = [[1, 0]]
```

这一步就是“光流看到的是什么”——互补滤波里的测量支路。

### 5. 初始化状态、协方差与噪声

| 符号 | 含义 | 本专题取法 |
|------|------|------------|
| `x0` | 状态初值 | 可取零或先验估计：`[v0, b0]^T`，默认 `[0, 0]^T` |
| `P0` | 状态协方差初值 | 必须正定，不能是零矩阵；常取对角阵，如 `diag(1, 1)` |
| `Q` | 过程噪声协方差 | 对角阵；`Qv` 置信模型灵活度，`Qb` 置信偏置慢变程度 |
| `R` | 量测噪声协方差 | 对角阵；本专题 `R = [[r_flow]]`，越小越信光流 |

`x0` 可以是零，但 `P0` 不行：`P0` 表示“初值有多不确定”，必须留出非零不确定度，否则滤波器初期不会信任量测修正。

`Q`、`R` 就是在告诉滤波器：预测支路和测量支路各自的噪声有多大，从而决定每时刻的 `K`。

### 6. 五大公式递推循环

前面已经得到：

- `x = [v, b]`：状态
- `F`、`B`：先验估计方程（加速度计推速度 + 扣偏置）
- `H`：观测方程（光流看到的是速度）

五大公式还缺过程噪声 `Q`、量测噪声 `R`、初值 `P0`——这些在第 5 步已列出。  
把它们填进公式后，每个采样时刻 `k` 先预测、再更新，循环输出目标状态。

缺什么、补什么的对应关系：

| 公式里出现的量 | 从哪来 |
|----------------|--------|
| `F`、`B`、`u` | 第 3 步先验估计方程 |
| `H`、`z` | 第 4 步观测方程 |
| `Q` | 过程噪声，描述模型多不准 |
| `R` | 量测噪声，描述光流多抖 |
| `K` | ③ 现算，由 `P⁻`、`R` 决定，不手填 |

**预测（Predict）——推进预测支路**

```
① x_k|k-1 = F · x_{k-1} + B · u_k
② P_k|k-1 = F · P_{k-1} · F^T + Q
```

**更新（Update）——用测量支路做互补融合**

```
③ K_k = P_k|k-1 · H^T · (H · P_k|k-1 · H^T + R)^(-1)
④ x_k = x_k|k-1 + K_k · (z_k - H · x_k|k-1)
⑤ P_k = (I - K_k · H) · P_k|k-1
```

说明：

- ③ 算出的 `K_k` 就是当前时刻的最优互补权重
- ④ 中 `z_k - H·x_k|k-1` 称为新息（innovation），表示量测与预测的偏差；④ 等价于  
  `x_k = (I - K·H)·x_k|k-1 + K·z_k`，即“预测与量测的加权融合”
- ⑤ 也可用 Joseph 形式，数值上更稳（本项目代码即采用该形式）
- 每步输出 `x_k` 即为当前目标状态估计；本专题取 `x_k[0]` 为滤波速度，`x_k[1]` 为偏置估计

伪代码：

```text
初始化 x0, P0, Q, R, F, B, H
for k = 1, 2, ...:
    收集控制输入 u_k、量测输入 z_k
    # 预测：模型推进
    x = F @ x + B @ u
    P = F @ P @ F.T + Q
    # 更新：互补融合
    K = P @ H.T @ inv(H @ P @ H.T + R)
    x = x + K @ (z - H @ x)
    P = (I - K @ H) @ P
    输出 x
```

对应本项目实现见 `卡尔曼滤波学习/service/kalman_filter.py`，循环入口见 `service/fusion_service.py`。

## 光流 + 加速度：完整落地对照

把“互补滤波两支”和“状态空间五步”对齐：

| 互补滤波视角 | 本专题具体量 | 状态空间对应 |
|--------------|--------------|--------------|
| 预测那一支 | 加速度计 `a_meas` 积分推速度，并扣偏置 | `u = a_meas`，`F`、`B`，公式 ①② |
| 测量那一支 | 光流速度 `z` | `H = [1, 0]`，`R` |
| 最优权重 | 每时刻自动算出的 `K` | 公式 ③ |
| 融合结果 | 滤波速度 + 偏置估计 | `x = [v, b]`，公式 ④ |

物理图像：

1. 加速度计把速度往前推一小步（预测）
2. 光流给出一个带噪的速度读数（量测）
3. `K` 决定这一步更信谁
4. 偏置 `b` 被一并估计，避免加速度积分越走越歪

只靠光流：抖。只靠加速度积分：漂。  
卡尔曼（互补滤波的最优形式）：短时信加速度计的平滑，长时被光流拉住不漂，同时把偏置估出来。

## 调参顺序

每次只动一个参数，按对数大约 10 倍去试。

1. 先定 `R`：让滤波速度比光流干净，但不要开始像加速度积分那样漂移
2. 再定 `Qb`：让偏置估计是慢曲线，不要跟着光流抖，也不要贴着 0 不动
3. 最后定 `Qv`：专门看加减速拐角和正弦段跟不跟得上

判断口诀：

- 蓝线跟着橙线抖：`R` 太小或 `Qv` 太大
- 蓝线像绿线一样慢漂：偏置没估好，增大 `Qb`
- 拐角明显滞后：增大 `Qv` 或减小 `R`
- 底图偏置乱抖：减小 `Qb`

换几次「重新生成」仍稳定，才说明参数不是拟合某一条噪声曲线。

从互补滤波角度理解调参：

- 减小 `R` ≈ 更信光流那一支
- 增大 `Qv` ≈ 让预测那一支更灵活、允许速度快变
- `Qb` 控制偏置这一状态“动得多慢”，间接影响预测支路会不会被错误积分带偏
